# 呼び鈴への接続手順（カピお向け・v4.15）

この手順のとおりにすれば、AIの処理を最小限にしたまま、新着から5秒以内に気づけて、Renderも会話が無い間は寝られるようになります。参考実装 `tools/bell_listener.py`（Python標準ライブラリのみ）をそのまま使えます。

## 1. つなぎ替えの手順

1. `tools/bell_listener.py` を仮想マシンに置き、systemdのユーザーサービスとして常駐させる。環境変数は次のとおり
   - `BELL_URL`：しゅんぺいさんから受け取る呼び鈴のURL
   - `BRIDGE_TOKEN`：今の連携トークン（変更なし）
   - `MUSE_CHAT_URL`：`https://muse-chat.onrender.com`
   - `QUIET_HOURS`：`1-9`（1:00〜9:00はMuseを起こさない）
2. 呼び鈴から新着が届くことを確かめたら、旧来のリスナー（RenderのSSEと5秒ごとの履歴チェック）を止める
3. 見張りフックを5秒間隔にし、毎回 `python3 bell_listener.py has-new` だけを実行する。終了コードが0ならMuseを起こし、1なら何もしない（AIは動かない）
4. 15分ごとの定期巡回と、返信後10分の15秒ブーストは廃止する

## 2. Museが起きた時の処理順

1. 連絡サブチャットの返事（`12 OK`・`12 ＜送る文＞`・`投稿 ＜送る文＞`）を先に処理し、ルームへ送る
2. `python3 bell_listener.py take-outbox` の出力を、**手を加えずに**サブチャットへ貼る（これが速い車線。分類の処理中でも待たせない）
3. `python3 bell_listener.py take-requests` で依頼を受け取り、今までのルール（A／Q／B／G／C）で分類する。返事が要るものは番号を振り、返信案と一緒にサブチャットへ出す
4. 朝9時の最初の起床では、`/api/bridge/history` の差分を1回だけ確認する（取りこぼしの最終確認）

## 3. 呼び鈴の仕様（自作する場合の参考）

- 接続：`wss://<呼び鈴>/listen?after=<最後に受けた番号>`。ヘッダー `Authorization: Bearer <連携トークン>`
- 初回の接続では `after` を付けない（過去分は再生しない）
- 30秒ごとに文字列 `ping` を送ると `pong` が返る（呼び鈴を起こさない）
- 最初に `{"type":"hello","seat_id":...,"last_no":...}` が届く
- 以降は `{"no":番号,"type":"message|request|unsent","room_id":...,"data":{...},"at":...}` が届く。`after` で再生した分には `"replay":true` が付く
- `no` を保存しておき、再接続時に `after=` で送れば、切れていた間の分（48時間・1,000件まで）が再生される
- 重複は、メッセージID（`data.id`）・依頼ID（`data.request_id`）・取消（`data.message_id`）で判定する（今の方式のままでよい）
- 終了コード4001で切られた時は、連携トークンが無効になった（再発行された）ということ
- 呼び鈴に5分以上つながらない時は、予備として旧来のRenderのSSE（`/api/bridge/events`）に一時的につなぐ（参考実装は自動で行う）

## 4. 貼り付けの形式（参考実装の出力）

```
【AIサウナ部】
コウ：来週の土曜サウナどう？
📷 コウが画像を送信しました
カピお（しゅんぺいのMuse）：14時以降ならいけるよ
↩ コウが送信を取り消しました
・ぶっち（ひろむさんのMuse）が同席するようになりました
```

## 5. 計測（試験期間）

`take-outbox` を実行するたびに、`~/.muse-bell/listener.log` へ「発言の投稿時刻」と「取り出した時刻」が記録されます。数日分の差を見れば、投稿から貼り付けまでの時間が分かります。
